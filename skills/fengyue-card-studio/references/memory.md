# 玫瑰信笺式长期＋短期记忆

沿用参考卡的`.rl-memory`折叠容器与两个独立表格。不要换成旧春水技能的蓝灰卡片，不把两张表合成一张时间流水账。CSS在`assets/reference-theme.css`，HTML在`assets/reply-template.html`。

## 结构与计数

长期列：No. / Time / Scene / Event；短期列：No. / Time / Scene / Layer / Event。标题显示长期M篇、短期k篇。计数行显示累计N轮、本组k/6。默认折叠，表格在内部水平滚动，手机整页不能被表格撑宽。

正式剧情含开局，每轮+1；先追加本轮一条STM。第6条形成时，当轮把这六条**包含当前第6条**合为1条LTM，保留已有LTM，并清空这组六条STM。N=5时M=0,k=5；N=6时1,0；N=7时1,1；N=12时2,0。LTM编号L01/L02，STM使用累计轮号。输出保留全部长期与本组未归档短期，而不是只给新增一行。

空表用`tr.rl-empty`，长期colspan4，短期colspan5，不计作篇数；有记录时移除空行。不把轮数当剧情日期。模板的`data-turn`、`data-base-turn`用于静态检查，即便平台移除属性，可见计数仍是承接依据。

## 单条长度与摘要方法

**每条STM的Event最多150字，每篇LTM的Event最多400字。**可按中文字符和标点计，校验脚本保守地按所有非空白Unicode字符计数。不是给每段paragraph各150/400，也不能把一个超长Event拆成多个表格行绕开上限。其它列只写序号、时间、地点、事实层，不把长摘要搬去Time、Scene或表外。

压缩顺序：删环境装饰和原句引用→合并同因果过程→保留人物、决定/行动、结果、关系/资源变化、未决期限。不要按字截断造成半句或遗漏“拒绝/未发生”等否定。具体日期、人名、承诺和信息来源比形容词优先。对信息密集的六轮允许删次要过程，不丢关键因果。

愿望、计划、猜测、梦境、转述与实际已发生分开；心声/后台信息确需保存时标读者视角，不让其他角色据此行动。原作设定放世界书，动态历史放记忆，不用每次归档重抄人物整篇简历。

## 表外三项也是当前快照

- 人物底稿：续写必需的稳定身份与关系锚点；不是全体人物完整档案。
- 有效事项：尚未完成的重要约定、期限和持续边界。完成的约定退出这里，其结果留在对应历史行。
- 续写位置：时间地点、实际在场/远程参与者、最后动作、待回应事项。只保留当前一处，归档时也不删除。

这些字段原位更新，不每轮新增“第N轮底稿”。不把Event里删掉的过程换地方继续堆。出现矛盾按明确更正与实际剧情修复，不伪造不存在的早期记录。

## 分支、纠错和迁移

场外提问/设定修改不增轮数；重新生成只继承该轮之前的同分支记录，不把不同候选都算经历。新局归零，正常续档承接原计数。历史不足时保留可见事实并标缺口，不补造六轮。

旧档无法恢复精确轮号时可用一次明确标注的迁移基准：data-base-turn=B；保留迁移前LTM，并给这些旧行data-legacy=true；之后本组从0重新计。标题包括旧长期，后续新增长期对应B+1起的六轮。只在真实迁移时使用，不用改B逃避归档检查。

## 消耗的实际边界

折叠不减少模型输入，CSS也无法删除平台历史。当前档案不累积，能解决重复输出和永久全员名单；保留所有长期则仍会随游玩缓慢增长。若长局遇到上下文压力，报告当前长期篇数与体积，提供用户可选择的“导出完整存档＋建立带来源的阶段摘要＋新会话承接”。未经用户选择，不悄悄删旧长期或把每6轮规则改成只留最近几条。不能同时承诺无限历史全量保留和上下文永远不增长。

## 摘要避免无效扩写

150/400字是单条上限，不是写满目标；信息少时如实简记，不用环境装饰填充。旧长期没有更正就保持语义稳定，不每轮润色加长；已归档的短期退出本组，不另复制到表外。人物当前态度、当前待办与历史因果各有主要位置，保留续写需要的短关联，避免同段经过在多个栏目全文重复。
