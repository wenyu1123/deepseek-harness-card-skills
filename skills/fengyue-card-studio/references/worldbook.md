# 风月世界书：内容、格式与触发

## 原生格式

此格式核对自作者提供的风月《世界书模板.json》。有更新的实际平台导出时以它为准，不猜字段。风月不同于春水的entries/categories或酒馆格式。

```json
{"world_book":[{"key":"_or_林遥@wb@旧书店","value":"【C001·林遥】林遥，29岁，经营临街旧书店。她正在修补一本进水的旧书，下午仍需出门取修好的台灯。谈到借书，她会先问读者真正想找什么，再决定是否推荐。她不会因为玩家进店就掌握其家庭秘密。","group":"人物","key_region":6,"value_region":1,"sort":20,"depth":2,"probability":100,"match_type":2,"enable":true,"value_type":0,"value_configs":[]}]}
```

|字段|含义|
|---|---|
|key|`_or_词A@wb@词B`为任一；`_and_词A@wb@词B`为同时；不使用逗号替代分隔符|
|value/group|正文/分组；显示标题放正文首行及作者索引，不乱加平台未定义字段|
|key_region|位掩码：系统1、用户2、AI4，可相加；6为用户+AI|
|value_region|位掩码：主提示词1、前置词2、后置词4；通常仅1，避免多处重复注入|
|sort/depth|插入顺序整数；扫描深度0—20。0的边界行为须以平台实测为准，不假设为常驻|
|probability|1—100，核心设定用100|
|match_type|2关键词选项，3正则|
|enable|布尔值|
|value_type/value_configs|0普通：用value及空数组；1概率：数组至少一个含value、probability的对象|

核心制度和输出协议宜放精简主提示词，不能靠任意关键词保证每轮注入。优先普通关键词；确有需要才用简单正则，不用前后瞻、反向引用或 `/pattern/flags` 这种未经确认的平台包装。脚本的正则模拟是Python近似，不是平台引擎证明。

## 内容层次与质量

- 核心人物：身份年龄、可辨外貌、背景资源、现在正在处理的事情、主要诉求与行为底线。读到这一条应能自然演出角色，不只有“温柔、腹黑、绝美”。
- 细档：关键经历按照“发生什么→她/他如何理解→现在留下什么习惯/矛盾”写。不要把几个形容词拆成十条。年龄、能力、职位、称谓、亲属和时间线相互核验。
- 性格写触发条件与表现，例如“不愿欠人情，接受帮助后会找机会实质回报”；再写压力下的偏离和不可随意改变的底线，避免一场互动彻底变人。
- 外貌描述发型、五官特征、姿态、服饰材质与生活痕迹，区分固定特征与可换衣着。不为堆细节随机添加身世、疾病或性经历。
- 人际关系分别记录双方知情、期待、误解与联系渠道。不因人物A知道秘密而让B自动知道。
- 地点要有可做的事、出入条件、时间规律、可能遇到的人及理由。组织要有资源、职责、矛盾和权限，不能只列名称。
- 事件写触发前提、人物意图、可选行动与可能后果，不强制固定胜负或让NPC替玩家选择。多个开局共享基础世界，互斥前提不能同时当已发生。
- 原作改编核对可靠资料并区分原作事实、作者改设与未知。不能编造查证结果。不要整段搬运版权正文。

## 触发设计

人物核心使用姓名、唯一别称和有理由的场景入口；“她”“女人”“今天”“喜欢”等泛词会造成常驻洪泛。多位人物共享地点时，用地点条目提供合理候选，不把全体档案绑定地点词。

`_and_林遥@wb@经历`要求两词同时出现；若用“姓名或经历”，每次“经历”可能调入全员。多个姓名别称×细档主题的复杂布尔式不由风月选项格式直接表达；可以拆成少量精准组合入口，或把足以演出的人物核心写完整，详细查询自然进入相关主题。不要为了省token把核心拆到模型根本拿不到。

状态栏反复写姓名，会导致扫描AI回复时反复触发对应条目，这是正常但有成本；更要避免每轮列全员。高成本回忆细档可优先扫描用户区域，减少模型自己的档案触发整本经历。不要承诺递归触发；地点中提到姓名不代表平台会继续加载该人物其他条目。

开局入口如`_or_开局一@wb@雨夜借伞`可扫描用户区域，条目正文限定“仅尚未开局或明确重开时使用”；不能每轮因为历史含开局词重演初遇。扫描深度按真实消息窗口调试，不无脑全20。

## 验证

执行 `python scripts/check_worldbook.py 文件.json --cases 案例.json`。案例数组每项为 `text`、`must`、`must_not`，索引以value首行`【C001·标题】`中的ID为准；也可提供`messages:[{role:"user",text:"..."}]`检查角色区域。

至少覆盖：只输入自然地点/事件也能遇人、别名、姓名+经历、无关闲聊不召全员、开局不会覆盖已进行故事（最后一项需人工语义检查）。输出命中的条目数量和字符估算。脚本不复现平台扫描depth，不把估算冒充实际token。

修复已有书保留未知字段与作者文本；导入更新先确认平台是覆盖还是追加，避免把整本书导入两次。世界书条目不是聊天历史日志，临时状态不逐轮写入永久设定。
