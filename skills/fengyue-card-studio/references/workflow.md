# 从构思到可导入成品

一般制作执行SKILL入口的省消耗要点。专项诊断/比较成本时再读 [efficiency](efficiency.md) 并运行只读工具；不重复加载全部参考，不凭字符变少判断质量。

## 1. 读资料并确定作品契约

先列出现有文件、平台导出/模板及作者偏好。用户已给出的参考卡是样式与结构依据，不代表必须复制其背景、人物性别或剧情。只有会改变核心作品的缺项才询问；其他项采用清楚标注的可修改方案并继续。

用简短创作契约确定：玩家是谁、能够改变什么、主要矛盾、人物各自想要什么、日常行动循环、长期发展、世界边界、自定义范围和多个开局之间的区别。先评估时间线、年龄、亲属关系、职业权限、地理和信息来源是否互相成立。不要用神秘伏笔替代人物动机，不把创伤仅当刺激装饰。

整卡交付也包含作品名与简短简介：体现具体人物处境和玩家入口，不泄露所有关键转折，不使用“无限自由、绝对真实”等无法兑现的承诺。基础信息中的封面、背景、标签、可见性等以作者决定为准，图片优先用其提供素材；不为凑流程自动生成图片、上传或发布。

## 2. 写设定，再拆成可调用条目

核心人物先写成连续的人，再拆条目：具体外貌、年龄与阶段、几次关键经历及后果、独立生活、说话方式、行为倾向、价值冲突、关系双向认知。世界规则说明限制、代价和例外。开局应给玩家有理由接触到这些人物的场景，不依赖玩家输入未知姓名。

参考世界书规范拆分为核心规则、人物核心、经历/细节、地点、组织、关系、事件与开局。规模由作品决定，不为了条目数重复改写同一事实。提供作者索引记录稳定ID、标题、触发与关联，禁止把索引全量塞进常驻提示词。

## 3. 写四个运行字段

先为这张卡写叙事与人物规则，再整合随附的状态/记忆协议及HTML骨架。主提示词负责权威规则和输出结构，前置词负责读取上下文，后置词负责本轮落地检查。三处不能各有一套不同的状态限额或轮次算法。无需单独创建供平台粘贴的“输出格式”。

人物资料丰富，不代表每轮必须重复全世界的人。正文要求与状态资料分开；不得拿状态表格凑正文字数。

## 4. 设计与开局

沿用参考卡的独立人物档案和双色表格，按题材调整文字、颜色、纹理和装饰。详细介绍要让新人知道：故事背景、主要人物、如何自定义、开局区别、第一条消息怎么发；不要仅写一篇宣传文案。

自定义至少支持玩家姓名/称呼、年龄、身份、外貌、性格、经历、与关键人物既有关系、开局与补充，分别用独立控件分栏填写，不能合并成一个大文本框。按题材决定性别、能力、穿越身份等；已固定的血缘/关键事件应说明可改范围。选填项留空仍可开局，年龄变更涉及时间线时联动调整。最后必须将已填资料与所选开局汇总为一条消息，并提供复制按键；原生details可折叠不等于完成自定义交互。

## 5. 文件与导入映射

默认在用户的卡文件夹下建独立作品目录，名称及路径由用户上下文确定。可采用：

|文件|用途|
|---|---|
|01_世界书_风月.json|仅导入风月世界书；根节点world_book|
|简介.txt|作品名与对外简短介绍，和详细引导页分开|
|世界书索引.md|作者查看ID、触发词与关系，不是模型常驻内容|
|主提示词/01_主提示词.txt|人设、规则、输出结构、状态和记忆|
|主提示词/02_前置词.txt|风月前置词栏|
|主提示词/03_后置词.txt|风月后置词栏|
|主提示词/04_内置CSS.css|风月内置CSS栏，仅CSS|
|引导页/引导页_复制到风月.txt|必须交付；完整网页代码，打开全选或通过复制工具复制到详细介绍，不是JSON|
|引导页/详细介绍_交互版.html|完整交互源码候选，含分栏填写、开局汇总和复制；平台保存需实测|
|引导页/引导页_完整预览.html|同一引导页的完整浏览器预览，介绍与交互功能在一起|
|引导页/详细介绍_粘贴.html|仅平台能力与保存重载验证后交付的版本|
|制作素材/引导页配置.json|内部构建输入；不是引导页成品，不交给用户自行转换或粘贴|
|预览/聊天样式.html|真实CSS与多人档案/记忆预览|
|复制文件.ps1、双击复制.cmd|选择并复制整份UTF-8代码|
|填写说明.txt|映射、复制方法、图片依赖、导入更新注意事项；区分浏览器通过与平台保存已验证|
|测试/验收记录.json|具体已执行检查、结果和未测试范围|

引导页在成品文件真正生成并通过 `check_guide_delivery.py` 后才可交付。最终答复直接链接“引导页_复制到风月.txt”和“引导页_完整预览.html”，分别说明复制与预览用途，不以配置JSON或一条待执行命令代替。

仅制作某一阶段时不创建虚假的其他成品。交付文件不能留“此处填写”、演示姓名、TODO或尚未替换的占位变量；技能模板中的占位符需在创作时填实。

## 6. 验收并交付

至少做一组多轮结构回归、世界书命中与误触发检查、移动端和桌面折叠预览、开局信息生成/复制验证。根据失败结果修复；完成后说明创建或替换哪些文件、哪段粘贴到哪个栏位。纯本地检查不能宣称已经在风月云端保存或真实模型试玩。安装技能不等于已经修改所有老作品。
