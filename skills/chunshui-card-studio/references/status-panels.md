# 分类折叠状态栏与输出预算

作者参考的是“纵向分类卡片”：有色标题条、小图标、简短字段、可展开的栏目。借鉴信息结构，不照搬参考作品人物、能力、身体细节或文案。不要把参考图的“思维链／质量管控”、阶段分析、自检报告、推理过程或内部计划打印成状态栏；只展示已知剧情事实与简短行动建议。

本文件用于写卡，必须将下方规则实际落实到人设与规则、输出格式和前后置词，不能只约束制作代理的说明。用户单独要求世界书/引导页时不扩大任务。

## 结构与栏目

一条剧情回复顺序为：正文 → 一份普通状态区 `section.cs-status` → 一份独立 `details.cs-memory-table`。普通区内按顺序使用以下五个栏目键，最多五个一级折叠栏。记忆区位于普通区之外，不参与普通区预算，仍严格沿用 memory-style 中150/400字及六轮归档规则。

| 栏目键 | 默认标题 | 内容与上限（含标题和标签） |
|---|---|---|
| world | 世界信息 | 时间、地点、环境、当前局势；最多4组字段，共120字 |
| self | 自身状态 | 身份与当前身体、资源、装备、能力/目标中的必要项；最多6组字段，共180字 |
| people | 当前人物 | 最多3名当前相关NPC，每名介绍最多90字，本栏共300字；外貌一处识别特征、可见举止、当前关系，按需选取 |
| threads | 进行中 | 最多3项当前待办/有效线索，每项最多40字，本栏共150字 |
| actions | 下一步 | 最多3条可选行动，每条最多25字，本栏共90字；没有行动推荐需求或已关闭时省去 |

普通状态区全部可见文字合计最多900字，包括栏目标题、提示、名字、标签、数值与标点，排除空白与HTML标签；这不是正文长度，也不是记忆总量限制。原始普通状态HTML含标签与空白最多6000字符，防止装饰标记比正文还长。没有必要的信息时宁可更短，不填满上限。不要求每轮五栏齐全：world/self作为剧情基础快照，其他栏目有相关内容才输出；空栏整体省去。

配色、图标、标题措辞可随作品修改，栏目键、预算及语义不变。日常可将threads叫“约定与待办”，修仙叫“历练与线索”；别给日常卡硬加修为，也别给无数值规则的卡编好感分。主题改动只针对普通区，既定记忆表格样式不跟着改。

## 写入“人设与规则”的底稿

```text
【状态栏：当前快照】
每条剧情回复只生成一份当前状态区，放在正文之后、长期/短期记忆表格之前。按本轮结束时的已知事实重新组织精简快照，不把上一轮状态卡HTML、已离场角色名单或过去各轮状态接在新卡下面。当前值变化就替换旧值；简短保留仍影响下一行动的时间、地点、伤势、关键物品归属与未完约定。不能只写“同上”或输出增量并假设平台会自动合并。

最多五个栏目：世界信息、自身状态、当前人物、进行中事项、行动建议。每栏最多一份，只有一层分类折叠；相关角色合在同一栏，不能每见一个人永久新增一张卡。world/self为剧情基础，其他栏目按需省略。正式剧情每轮给出精简快照；场外问答、参数调整不自动重发整套状态。不要输出思维链、阶段检查、自检结果或内部写作计划。

【容量与内容选择】
普通状态区合计最多900字，原始HTML最多6000字符，不包含正文和独立记忆表格。字数按去除空白的可见字符计算，含标签文字、标点和数字，不含HTML标签；各栏也须满足更小上限：world最多4组字段/120字，self最多6组/180字，people最多3人/300字且每人最多90字，threads最多3项/150字且每项最多40字，actions最多3条/90字且每条最多25字。这些都是上限而非凑满目标。装饰交给内置CSS，回复不附style、script、Base64图片、重复SVG或长内联样式。

展示优先级：眼前紧急情况、当前对话/行动对象、下一步必须知道的约定和物品。超过3名在场人物时，选最相关的3名，其他人的具体表现仍可在正文自然出现；不能将“未展示”写成离场或不存在。离场且与当前事无关的人不占状态行，有关事实在记忆中延续。伤势未恢复、关键物品未交还、有效约定未履行时必须保留相应短记录，其他低影响信息让位。

每个事实选择主要栏目展示：时间地点在world，玩家伤势/装备在self，NPC当前举止与关系在people，待办在threads，备选行为在actions。普通栏内不把同一事实换个标题重复抄一遍。关系变化并入对应人物，不另外维护不断扩张的全员关系网；行动建议由作品或MOD统一出一组，不能两边各输出一次。建议和猜测不记为完成。

完整履历、详细年龄外貌经历、完整技能说明、全量背包与历史关系由世界书/既有记录按需提供，不每轮粘贴。外貌只在当前需要识别、发生变化或玩家询问时写一处短特征；衣着历史、过去心情和完整恋爱经历不逐轮重复。已解决任务移出进行中栏，其实际结果纳入本轮记忆，不把完成项无限挂在状态末尾。不另加逐轮增长的时间线或日志；历史事件统一交给LTM/STM。

超过预算时删重复与无关项、合并措辞、把字段改短，保留关键当前事实；不能用隐藏、折叠、字体缩小、CSS裁切或堆进记忆辅助区来假装减少输出。省略展示不等于删除已知事实，不能为省字改写历史。

【详查与场外】
玩家明确要求完整人物档案、全量背包或关系历史时，按所查范围做一次专项答复；长清单可分页，结束后恢复精简模式，不能从此每轮携带全部清单。明确要求精简/关闭普通状态栏时遵从，不连带关闭或清空记忆。恢复显示时依据当前可见记录生成快照，不谎称可恢复不可见资料。
```

## 文件与样式契约

- 结构母版：[status-panels.html](../assets/status-panels.html)。将片段加入实际“输出格式”TXT，说明占位全部替换；按题材填字段，删除空的可选栏目，禁止把注释或占位留在最终回复。参考图的角色不能被带进其他作品。
- 成品CSS需实际包含 [status-panels.css](../assets/status-panels.css) 和既有 [memory-table.css](../assets/memory-table.css) 的内容，分别作用于普通区与记忆区。不要只给本机link路径让平台自行读取。
- 一个 `section.cs-status` 内，每个 `details.cs-panel` 有唯一 `data-section`（world/self/people/threads/actions）。每栏summary采用小图标、栏目名和短标记，主体使用简短键值或条目。NPC用 `article.cs-person data-person="姓名"`，禁止嵌套折叠树和固定id。
- 默认world展开，其他普通栏折叠；记忆仍默认折叠。全部展开与收起只是阅读操作，不是消耗优化。桌面亦保持纵向分区，手机字段自动换行，点击区域至少44px。
- 只把状态正文片段写进每轮输出；CSS放平台内置CSS一次即可。状态栏不执行存档合并、不回写旧消息、不擅自删除聊天；这些能力需平台真实支持，不能用提示词或不存在的JS接口冒充。

NPC与清单条目结构如下，替换成作品事实；没有人/事项时删除整个可选栏目：

```html
<article class="cs-person" data-person="人物姓名"><h4>人物姓名 · 已知身份</h4><p>一处识别特征、可见举止或当前关系的必要简述；本条全部可见文字最多90字。</p></article>
<li>一项未完成事项及期限（最多40字）。</li>
<li>一条尚未执行的行动建议（最多25字）。</li>
```

## 前后置与MOD接入

前置增加一句：`承接最近有效记忆和当前现场，确定本轮真正相关的状态与人物，不将历史角色表整体带回。`

后置增加一句：`普通状态只出一份当前快照，至多五栏；遵守900字/6000字符及各栏人数条目上限，去掉旧HTML、全量履历和重复时间线，保留关键当前事实；记忆另按LTM/STM规则输出。`

只增加短提醒，完整预算写在人设规则和输出格式两处一致。输出格式必须含上表的具体数值，不能仅写“精简一些”。行动MOD遵守actions的3条/25字限制，统一复用一个actions栏目。

## 防堆积验收与能力范围

运行 `python scripts/check_status.py "实际样例.html"`，检查普通区数量、栏目唯一、人数/条数、逐栏/全区字数及原始HTML长度；样例不能只放一个空框通过。配合 `check_memory.py` 验证独立记忆仍正常。

默认检查对象是开启状态展示的正式剧情回复。明确关闭状态的回复、场外答复和专项档案查询不强制套用该默认结构，按各自约定单独验收；不要为了通过检查擅自恢复玩家关闭的状态栏。

至少准备日常一人、多人超过3名、人物离场、任务完成、强行追加旧状态、重复行动MOD、长字段和第30轮场景。确认多轮普通状态大小受预算约束，离场者不继续常驻，状态中没有全历史时间线；不是仅把过长栏折叠起来。一次详查之后，下一轮回到精简快照。显式保留长短期记忆，不用删除LTM换取测试通过。

已有卡出现堆积时，先检查输出格式是否要求全量角色/全履历/全物品/全部日志，主规则与前后置是否重复要求追加、MOD是否再加一组。修改成品规则与模板，清除矛盾指令；更新skill不等于自动改好已发布卡或旧聊天。

折叠不会缩短模型已生成和已发送的文字。该方案约束新回复的普通状态负担，不会抹除旧消息、不控制平台的上下文裁剪或世界书加载，也不保证总token/费用恒定。作者已要求累计LTM不删，本轮继续保留；长期记忆随剧情累积依然占上下文。报告字符数与HTML长度，不能当作精确token数或承诺固定省费百分比；未做真实模型多轮试玩须如实标注。
