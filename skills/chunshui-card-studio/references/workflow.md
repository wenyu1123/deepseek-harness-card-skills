# 从概念到可玩的卡

一般制作执行SKILL入口的省消耗要点。专项诊断/比较成本时再读 [efficiency](efficiency.md) 并运行只读工具；不重复加载全部参考，不凭字符变少判断质量。

## 1. 确认最少的关键点

从对话推断已有选择，不重新问一整套问卷。需要确定：题材；玩家是谁；主要交互对象；日常/冒险/权谋等玩法；默认或可选开局；平台；本轮范围；输出位置。其余可先给合理参考，并标为可改。

为完整卡建立一页母稿：一句话卖点、玩家能做的三件具体事、首个可回应事件、长线目标、关键不变量、自由变量。不要用“高自由度/全员可攻略”替代具体行动与后果。

例：旧书店经营者在雨夜发现一封旧信 → 请修书师辨纸 → 花时间修复 → 获得地址 → 决定是否找人。日常卡也可以是“见面—提出需要—回应—形成新习惯”，不必硬加战斗数值。

## 2. 文件与版本

建议目录，按本次范围增减，不生成空壳假装齐全：

```text
作品名/
  00_使用说明.txt
  01_世界书_导入.json
  02_世界书_阅读版.txt
  03_触发目录与测试.txt
  主提示词/
    01_破甲词_沉浸约定.txt
    02_人设与规则.txt
    03_输出格式.txt
    04_内置CSS.css
    05_前置提示词.txt
    06_后置提示词.txt
  引导页/
    引导页_直接粘贴.txt
    引导页_本地预览.html
    背景图.webp
  源稿/世界母稿.json
  源稿/引导页配置.json  # 内部制作输入，不是引导页成品
  测试/检查记录.json
```

引导页必须实际构建为完整代码：`scripts/build_guide.py 源稿/引导页配置.json --out 引导页`，再执行`check_guide_delivery.py 引导页`。最终直接交付并链接TXT与HTML；不得把源稿JSON、测试JSON或一条构建命令交给用户充当引导页。复制工具`scripts/copy_files.ps1`放作品根目录并命名`复制文件.ps1`，配套`assets/双击复制.cmd`；第7项复制引导页完整代码。

机器JSON建议UTF-8无BOM；供Windows记事本阅读的TXT可用UTF-8 BOM；HTML标注UTF-8。文件名直观区分导入文件、阅读稿和源码。不要把内部母稿误标为平台导入文件。世界书目录保留条目名、别名、分组、触发范围与测试句。

在原作上重做且用户说原作不改时，创建新目录/版本；若用户授权修复，先保留原文件副本，再写目标文件。沿用稳定ID，不因排序变化生成新ID。不要对整张桌面“清理”或递归删除。

## 3. 春水栏目分工

| 栏目 | 内容 |
|---|---|
| 基础信息 | 名称、简介、标签、受众、封面、桌面聊天背景、移动背景、可选音乐 |
| 主提示词/破甲词 | 简短沉浸约定 |
| 人设与规则 | 叙事职责、世界核心、玩家控制、记忆更新压缩与人物/文风连续性规则 |
| 输出格式 | 分类折叠普通状态（唯一当前快照及人数/条目/字数预算），外加独立LTM/STM记忆；详见status-panels与memory-style |
| 内置CSS | 与输出结构配套的纯CSS，不夹HTML和提示词 |
| 前后置词 | 少量当前理解和回复收束规则，不重复整本世界书 |
| 世界书 | 角色、地点、势力、制度、事件、过去经历等按条件注入的资料 |
| 引导页HTML | 给玩家看的介绍、角色目录与开局表单 |
| 平台美化 | 平台外围界面CSS；选择器需实际检查，不能套聊天class冒充 |
| 设置 | 开场白、问题建议、快捷指令、CG等，按当前编辑器实际项填写 |

截图只证明看得到的字段，不证明运行时接口、文件格式或发消息权限。拿到原生导出先做最小导入样本，再扩展。

## 4. 内容阶段

深度验收见 [quality.md](quality.md)。世界书按 [worldbook.md](worldbook.md) 先写相互约束的事实与人物，再拆触发条目；完整新建或重做增加一个测试/世界书场景.json，以 [worldbook-audit.md](worldbook-audit.md) 校验出场路径和加载量。先完成核心作为内部组织步骤，之后继续扩展到本次要求的范围，不能在“最小核心”处结束交付。用户要求的角色、年龄/外貌/经历、玩法和页面交互列入本轮检查项；只需简短列明，无需另写冗长策划报告。

从可玩的最小核心建立系统，再扩到用户要求的规模。用户要求80+ NPC时应完成要求，不擅自缩成“先给10个”；可分组编写、记录计数，省略重复规则以控制消耗。

同人核对官方资料或用户提供的原文，标明所取时期、原作事实、推断与原创延展。不要把未检索到的剧情补成事实，也不纳入用户明确排除的续作。新版本角色数量和经历可能变动，缺工具时说明核验范围。

简介给玩家看：身份、场景、关系张力、可玩行动、自由选择。不要把系统指令、秘密动机全文、技术安装说明当简介。

## 5. 体验与成本

常驻提示只保留稳定规则；详细档案分条。人物核心可短，外貌、经历、相处、能力和制度另分条，不用每轮加载所有人。把正文字符数、整包大小、常驻量、代表场景命中量分开报告；未使用匹配模型分词器时不把字符数称为token数。

长任务将设定与进度写入项目文件，避免每一步重复读旧聊天或所有资料。代码压缩与图片外链减少粘贴负担，但阅读版与源码保留换行。压缩不能删掉必须的设定。节省创作消耗与节省玩家每轮上下文分别处理：完整档案可详细，运行时按场景触发；不要把两者混为“所有内容越短越好”。

## 6. 上线之前

完整卡的主提示词按 [记忆与叙事模板](memory-style.md) 落实默认记忆组件和逻辑约束；使用说明注明如何查看、纠正、整理和复制记录续局。若本次只做世界书或引导页，不借此提前制作主提示词。

先按qa测试结构、触发、状态与页面，再给出保存/试玩位置。保存草稿、保存模型参数、公开发布是不同动作。界面出现内容不是已保存证据。公开、付费、上传到外部图床或覆盖既有作品需要对应授权；只准备文件不需要额外确认。

如果要教新人，按栏目提供短示例与“放在哪里”，先做能对话的小卡，再讲世界书与美化。没有文档工具时可交付Markdown教材，不假装生成了Word文件。
