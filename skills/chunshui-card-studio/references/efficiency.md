# 保持内容质量的成本控制

本文件同时用于制作成本与玩家游玩成本，两者分别度量。原则是去掉重复、无关注入和重复劳动，保留事实、人物深度、视觉与交互质量。不能用更短正文、少写人物、删重要经历或省略验收冒充优化；不按耗时长短判断是否认真。

## 1. 制作时按需读取、局部修改

- 先用文件列表与定向搜索定位当前资料。读过且未改的规范/源稿在本轮不反复全文读取；上下文丢失时先读项目交接摘要，再读相关原文，不凭记忆猜。
- 世界与人物保留一个可维护母稿；导入JSON、阅读版、索引、引导页配置从它派生。长资料分组写入文件，工具返回路径、计数、差异和错误，不把已落盘的整包内容再次贴回聊天。
- 修改某个人物时，检查其关系、出场入口、引导页和首遇的相关引用；修改CSS时检查相应HTML和可视结果。局部重建所有受影响衍生品，不重写无关人物、故事或整套模板。
- 单次测试通过且相关输入没有改变，不为显得认真反复运行。新增或修改的功能执行有意义的回归；CSS/布局改动仍需看图，表单/复制改动仍需实际浏览器操作。
- 规则与结构回归使用离场、回归、归档、更正等小型确定性夹具；正文长度和审美另用真实长度的代表样例检查。不为测轮号机械生成30篇2000字小说，也不把静态夹具说成模型试玩。
- 完整任务必须完成所有约定阶段；按需读取不是只做核心就提前交付。交付配置和生成后的TXT/HTML，不让用户补跑脚本。

## 2. 常驻提示词各有职责

主规则负责世界定位、人物连续性、玩家控制、叙事与记忆协议；输出定义只保留一份结构骨架。前置词只帮助理解本轮意图，后置词只放简短执行提醒。已有明确篇幅、记忆上限等关键提醒可以重复一行，不能把整套协议或世界书复制三遍。

把完整角色简历、地图百科与支线资料留在世界书。常驻核心必须足以保证人格、制度、知情边界和连续性，不能为了变短只留“按世界书执行”。完整介绍、技能说明、构建配置、测试记录、来源目录不进入聊天提示词。

春水：人设与规则定义协议，输出格式保留唯一骨架，破甲栏仅短沉浸约定。风月：输出结构整合在主提示词，不凭空增加独立输出格式栏。内置CSS只安装一次，模型回复不重发style/script/Base64或整张引导页。

## 3. 世界书完整存档、分层调用

保留全部约定人物与资料。人物核心含可辨身份、性格动机、关键经历对当下的影响和接触方式；缺它会OOC的信息不能只放在低概率详档。相对独立的长经历、地点细节、支线资料按需要触发；已经足够紧凑的条目不要为条目数量再拆碎。

姓名/唯一别名定位人物核心，不把同一名字无条件绑定此人的所有细档。通用“外貌/经历/性格/过去”不作为全员详档的OR触发；用平台已支持的组合或自然查询短语，并测试合理的多种问法。地点给当前场景候选和足够接戏的信息，不因进入城市加载全城人物，也不依赖未验证的递归加载。

通常只选一个注入位置；多位置是有意设计才保留。高成本回忆详档可优先看用户消息，人物核心仍要支持最近人物及“她/继续”的承接。扫描窗口依据平台能力与真实场景调试，不统一缩到最短、不靠降低概率漏载核心。

必测：自然称呼、别名、无姓名进场、相关细节查询、无关同词、指代续接、离场后换场。报告命中条数与正文字符；不能删掉失败用例、未命中角色或必要内容来换较低数值。

## 4. 状态详细，但同一信息不要多处扩写

沿用作品的详细字段、固定特征、内心与已知关系；风月继续不设状态字数硬上限。不得因本规则给任何作品新设或收紧人物、状态、正文上限。

每轮按当前实际参与者生成一份自足快照。人物固定资料可详细，不每轮追加新的“补充说明”；衣着、位置、身体、心声直接替换旧值。完成/取消事项离开当前待办，重要结果记入历史。离场者停止常规显示，回归承接已有事实。

为重复信息指定主要位置：人物卡写此人的当前态度与必要原因；共同事务写跨人物未决事项；记忆写已经发生且影响未来的事件。一个承诺可在当前事项中短列期限、在历史中记成立原因，这是有目的的重复；不要在关系、日程、事务、底稿和每条记忆五处复述同一段经过。

没有实际变化的栏目不硬凑新进展，不能为了省消耗丢掉已知稳定资料，也不能只输出“同上/其余不变”或增量补丁。未确认的平台没有自动合并旧HTML/隐藏数据库，details折叠、display:none、注释和压成一行都不等于减少模型要读的内容。

## 5. 记忆保留因果，上限不是写满目标

短期单条Event≤150字，长期单篇Event≤400字，每6个剧情轮归档并包含第6轮，保留已有长期。只记当事人、关键决定、结果、变化和未决期限；保留否定、来源、具体时点与身份关系，删装饰、引用和无意义日常流水。信息少的事件可以短，不为接近上限扩写。

归档后这6条短期退出当前STM，不在其它栏目另抄一遍；旧LTM没有更正就保持语义稳定，不每轮润色扩写。只重新输出目前应有的LTM与本组STM，不能嵌入历次整表。人物底稿/有效事项/续写位置原位更新，不成为第二本全量档案。

全量长期历史仍会增长。不要改成偷偷删除旧长期、只留最近几条、拉长归档周期或自动开启新局。用户选择时才提供完整存档与有来源的阶段摘要续局，并说明摘要可能损失细节。普通提示词无法自动清理平台消息，也不能宣称自动获得缓存折扣。

## 6. 可测量、可回退

同一作品优化前后使用相同人物范围、同一组输入场景与相同回复类型比较。先确认事实/人物/出场路径和交互没有缺项，再看重复量与无关命中是否下降。数字变小本身不是验收通过。

运行 scripts/audit_cost.py，显式传本轮相关文件，可重复传参：

- --prompt：实际进入模型的主/前/后提示词、春水输出格式。不要把CSS、引导页或完整技能算作每轮主提示词。
- --worldbook：平台原生世界书JSON，统计存档量、重复正文、共享关键词和多位置注入候选。
- --scene-report：已有世界书触发工具的结果JSON；春水使用audit_worldbook结果，风月使用含cases的check_worldbook结果。这里只汇总，不重新模拟平台。
- --reply：按时间顺序给代表性HTML回复，分别看状态、记忆、内联样式及重复人物ID。非默认CSS前缀需先适配ROOT_CLASSES；未识别不是零消耗。
- --baseline：优化前的本工具报告；仅在同一组文件职责、人物和场景条件下比较。
- --out：项目测试目录的报告路径。已有报告需明确使用--overwrite；工具不得覆盖源文件。

例：python scripts/audit_cost.py --prompt 主提示词/01_主提示词.txt --prompt 主提示词/02_前置词.txt --worldbook 01_世界书_风月.json --reply 测试/回复.html --out 测试/成本检查.json

工具只用标准库，只读素材，不联网、不调用模型、不自动缩写文件。字符不是token；未用匹配模型分词器/账单时不估计精确费用或百分比。格式化JSON文件大小不等于世界书注入成本；所有样例相加也不等于单轮费用。重复提示是人工审查候选，不用于机械删除。
