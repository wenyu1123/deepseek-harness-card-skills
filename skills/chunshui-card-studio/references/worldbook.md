# 世界书：人物有来路，世界能运转，资料能触发

本参考用于新建、扩写及修复世界书。局部修复只执行相关项，保留原作与稳定ID。内容深度以用户要求为准；“尽量详细但注意消耗”意味着作者资料写完整、运行时按需加载，不等于削成标签。

## 1. 先确定什么是真实发生的

从现有母稿/原生导出核对世界、年代、玩家身份、主要角色、开局分支、规模和用户禁改项。在母稿中维护少量“事实锚点”：稳定姓名/ID、年龄或年龄关系、亲属/师徒/职位、时间线、地理移动、制度称谓、能力边界。其他文件从这里导出；改动时同步引用，不能留下两份互相矛盾的身份。

区分四类信息，写进条目正文而非仅分组名：
- 已确立事实：时间、发生过的事件、目前持有的物品与关系。
- 角色认知/传闻：谁相信什么、证据是什么；不可直接当真。
- 作者秘密：客观真相与知情者、可查证线索；NPC不能凭作者视角读心。
- 条件事件：尚未发生，满足前提才有机会发生；关键词命中只加载资料，不代表事件发生。

同人先定版本与截止时期。重要身份、外貌、阵营、原世界经历和关系核对官方原文或用户给出的资料，来源记录放作者母稿/参考表，不在每条正文重复长网址。明确“原作事实/合理推断/本卡原创”；未公开的年龄、身世不要编成官方设定。穿越卡保留抵达前的记忆、能力代价与牵挂，都市适应经历另记；不能把角色变成只会依附玩家的空壳。没有检索工具就标明核验范围，不假称查证。

## 2. 人物深度按重要性分配，不能按模板注水

先完成一位主要角色作为质量基准，再逐个完成本轮全部人物。重要角色至少能从档案中回答下面的问题；写成自然紧凑的段落，不强迫所有人使用相同标题或字数。普通路人不必拥有同等长的身世。用户明确要求所有NPC详细时，逐一完成，不能只认真写主角。

| 维度 | 必须提供的具体内容 | 常见空壳 |
|---|---|---|
| 身份与生活 | 年龄/年龄关系、职业职责、住处、常去处、资源与日常安排 | 只有头衔，职位仿佛无所不能 |
| 外貌与动作 | 识别点、身形姿态、脸/发/眼、常服与场景变化、习惯动作；有现实可见的质地 | 人人绝美、精致、完美身材；一整段互换无差别 |
| 经历与能力 | 不同阶段的重要经历、当时选择、所得与代价、如今留下的证据/习惯；能力的学成过程 | “经历坎坷，所以腹黑”，历史与现在完全无关 |
| 动机与反差 | 长期追求、眼前打算、害怕失去什么、盲点、底线、变化条件 | 平时温柔，一受刺激就换人格 |
| 行为与声音 | 平静/被拒绝/利益受损等情境的不同反应；有辨识度的说话方式及短对白 | 全员同一个嘲讽腔或强制亲昵称呼 |
| 独立性 | 玩家不来时也要做的事、与旁人的合作/冲突、拒绝玩家后仍可成立的行动 | 所有角色只为攻略、嫉妒或交任务存在 |
| 入场与发展 | 从哪里遇见、此刻在做什么、可回应的需求、关系改变的可观察证据 | “可随机邂逅”“后续自由发挥” |

经历 → 当前信念 → 选择 → 行为 → 别人的反应，要能连起来。性格反差解释为同一动机在不同条件下的表现，而不是任意开关。不要给所有人套“童年创伤→缺爱→控制欲”：骄傲、职业伦理、兴趣、友谊、利益、责任同样能驱动人物。描述衣着与身体只在影响识别、动作或情境时展开，不要求聊天每轮从头扫描外貌。

关系写双向：双方分别如何看待对方，源于哪件具体事，合作依赖什么，冲突卡在哪里，什么行动会改变关系。重要人物应有与玩家无关的关系；不要预定所有人必然喜欢、敌视或服从玩家。口头拒绝、利益冲突、和解都必须与已有动机衔接。

## 3. 世界规则必须落到可行动的场景

地点不止风景：位置/路程、开放与进入条件、谁在做什么、能获得什么、可能付出什么。势力不止名字：目标、资源、内部差异、管辖与合作边界、与别家争什么。制度说明谁能做什么、由谁执行、违规会有什么后果、例外如何成立。

按题材选择必要系统。日常卡可写工作排班、租住、收入开销、人情往来；古代王朝写官制、继承、礼法、地域与民生；修仙写境界能做到什么、做不到什么、突破条件、资源代价及阶层影响。不能只有名词表或数值阶梯；也不要在普通恋爱卡硬塞战斗经济。

女尊等制度性世界：明确当权/继承/科举/婚姻的资格与称谓，按世界设定统一皇女、储君等头衔；社会权力、个人性格、身体特征和自我认同分别描述，不能只把男女代词机械替换。反例复核：一个无资格者能否无缘由变成储君或官员？如有例外，必须有本世界的具体依据。

可玩事件至少给出：发生前提、参与者当下目的、可观察起因、玩家能做的不同事情、各自代价或机会、拒绝/拖延后的变化、再次发生条件。只提供合理可能，不替玩家决定行动，不把未发生的结果写成记忆。没有时限的事件不要凭空倒计时；需要调查的真相不能在入口旁白全揭晓。具体例子见 [worldbook-example.md](worldbook-example.md)。

## 4. 时序和人设先校对，再拆条

明确时间锚点。年龄确定时核算“现龄−事件发生年龄＝距今几年”，亲属年龄/入学任职/学习时长一起核对；不要既写43岁时孩子18岁，又说生育发生在二十多年前。玩家可自定义年龄时优先采用相对阶段；影响角色年龄或亲属关系的地方给一致的推导规则或可选版本，不把所有固定年表一起保留。所有开局先有选择条件，互斥事实不同时生效。

对主要人物用短情境检查而不是生成冗长思考过程：玩家拒绝帮助、第三人介入、利益与感情冲突、暂时离开、提出与设定矛盾的称呼。复核档案能否支撑相应行为。记录结论和对应条目，不输出思维链。实际模型未试玩时称“设定审查”，不称“已验证不会OOC”。

## 5. 详细内容与触发成本分层

优先复用稳定平台字段；类型参见 [schema.md](schema.md)。较小人物档案不必拆得粉碎。大型档案按以下职责拆分，条目应能单独读懂；避免把同一段复制到多个条目。

1. **短核心**：世界类型、重要制度不变量、互斥开局处理等少量基础事实。不要把长篇正文规范、全员履历、每轮状态输出规则塞入多个常驻条目。
2. **场景入口**：由地点、职业/组织和当前事件引出相关NPC。正文直接给该场景少数NPC的姓名、身份、当下动作与交互线索；即使平台不递归，仍能自然引出人物。
3. **人物核心**：全名/独有别名触发；保留足够识别、动机、底线、关系与当下行为线索，单独加载也不会失去人格。细节可索引到专名查询。
4. **专题详档**：经历、外貌、能力、复杂关系按需查询。入口中提供自然短语，如“问林知夏的旧事”；不绑定所有人物共用的“经历/性格/她”。关键且影响当前行为的事实先放人物核心，不能仅藏在需精确暗号的档案中。
5. **条件事件**：场景词载入后仍需判断前提、一次性/冷却与当前进展，不因重复提词反复播开场。

每位重要NPC至少有一条非姓名出场路径：已知地点、组织职务、任务介绍或其他NPC的合理引介。不要把几十个人放在同一个广义城市入口；按地段/场景分流。每组抽查主要人物之外的成员，验收“玩家不知道此人的姓名也能遇见”。作者母稿中的详档如果没有导出或触发路径，模型在游玩时并不知道；不能把保存在硬盘等同于已供模型使用。

### 匹配方式取舍

- 普通关键词OR是默认，优先唯一名称和自然短语。不开中文全词匹配的盲目开关；宽泛词不是越多越好。
- OR列表`[林知夏, 经历]`不是“林知夏且经历”，任一词都会命中；把姓名挂在该人物所有详档上也会每轮整套注入。
- 确认平台原生主/次关键词的AND语义后才能用双条件。未确认时采用角色专名短语并提供入口提示；存在自然措辞覆盖不足时说明限制，不能写不受支持的环视来“修复”。
- 平台已报过不支持lookaround/backreference；禁止用`(?=...)`、`(?!...)`或反向引用模拟组合条件。复杂正则必须经实际目标引擎验证；不要用Python/JS通过代替平台验证。
- 触发扫描默认限定最近user/assistant，详细查询优先user；不要全局扫system导致世界书互相触发。深度、优先级方向、递归、预算裁剪都以平台实际行为为准。
- “继续”在有近轮上下文时可保留在场人物；孤立的“继续”不应加载全人物库。离开且过了扫描窗口后旧场景应退出；仅命中不代表资料被持久保存。
- 中文条目名与触发词分开；展示正则字符不是编码乱码。JSON/界面是否保留entryName要看实际回读。

## 6. 验收不能只看条目数

创作或完整重做时建立一个轻量检查记录，放原有测试文件即可：用户需求→对应条目；重要人物→非姓名入口；关键关系/年表核对；未核实的同人信息。不要为了报告另产一套同等长的档案。

执行 [worldbook-audit.md](worldbook-audit.md)：结构有效、重复/宽泛触发检查、自然场景正反例、命中字符量与遗漏覆盖。全书初检后，修复仅复跑受影响项；修改触发公共规则时扩大回归。发现具体失败先修复，不得调宽预算、删负例或隐藏unsupported让报告变绿。

最后进行内容审稿：主要角色逐一核对，配角逐组抽样，用户要求全员详写则逐人核对。去掉姓名，重要人物的经历/口吻/处事是否仍有区别？去掉人物档案，场景是否还能引出人？只加载核心与入口，能否解释其当下行为？不同选择是否真的改变局面？找出缺证据或矛盾的具体句子并修复，不以字数达标、评分高或JSON成功代替质量。

报告完整作者稿字符量、已导出条目量、常驻候选量和代表场景命中量；没有实际分词器不要称为tokens。预算按作品规模和实际模型/平台协商，常驻短、场景相关、详档按需，不用所有题材一套硬性篇幅。普通状态区900字/6000HTML限制仅属状态栏，不能偷换成整个世界书上限。
