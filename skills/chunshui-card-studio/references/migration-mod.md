# 迁移、MOD与重做

## 迁移

先盘点源：世界书、系统提示、前后置、开场白、介绍HTML、CSS、图片与现有存档规则。再核对目标平台真实字段。名称相似不代表注入位置相同；原生导入JSON、SillyTavern卡、世界书JSON和整作品JSON不要混用。

有目标原生样本时映射字段并保留内容。未知格式时先交付分栏文件，不把猜测schema标成“一键导入”。外部图片链接需检查可访问性；旧平台的点击事件或全局函数需替换为已验证接口或手动复制流程。

迁移前后对照：人物数量、条目数量、ID、引用、年龄/称谓、原著时期、重要事件、关键词、CSS class、图片和开局是否一致。只在目标中新建草稿，不无授权删除源作品。

## 行动推荐MOD

通用MOD不写死人物、门派、朝代或能力。按当前场景、玩家身份、已知资源与真正可行的下一步给通常3条可自由选择的建议，每条最多25字。三条应有不同方向，例如推进当前事、了解人物、整理/休息；紧急场景服从当前处境，不硬给闲逛。

建议是尚未执行的选项，不提前算进记忆；不揭示玩家未知秘密，不承诺必成功，不抢玩家决定。支持玩家自由输入、选择编号与关闭建议。作品已有建议栏时复用一个 data-section="actions" 栏目，不在状态栏前后各生一组；一组最多3条，总栏最多90字，纳入普通状态900字预算，见 status-panels.md。

交付名称、简短描述、标签及MOD系统/前置/后置字段；前置可空，后置只做短提醒。平台截图出现“未关联=万用MOD”时可据此配置；没有看到真实设置不要承诺装一次自动应用到所有作品。公开可见性与价格按用户决定，默认不会替用户发布或收费。

MOD避免覆盖作品整份系统提示。若涉及CSS，固定命名前缀、不改平台全局，并给出所需HTML结构契约。

## 重做与排错

把反馈变为可测试约束，而不是给模型重复喊“必须”：

- 人设变形 → 稳定核心、情境反应、目标与变化依据；删冲突规则。
- NPC只遇到一个 → 地点/组织/事件入口携带姓名与最小身份，检查扫描范围、命中与预算。
- 女尊冒出男性继承人称谓 → 明确本世界继承制度与女帝/皇女/皇太女称谓，逐字段核对，不做机械性别替换。
- 要穿越或修仙 → 独立可选身份、时代知识边界、力量来源与代价，避免所有路线同时成立。
- 正则保存失败 → 查看具体错误，使用普通关键词和确认支持的原生匹配；改完检查整包同类表达式。

修复的验收场景应能重现旧问题，并确认无关设定未被悄悄重写。
