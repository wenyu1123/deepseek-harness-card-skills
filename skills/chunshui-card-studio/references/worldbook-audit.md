# 世界书审计：结构、触发与审稿分开

脚本是只读的标准库工具，不调用模型、联网或改写作品。新建/完整重做用完整场景集；扩写/修复重点回归受影响人物和公共触发规则。审查结果写入作品现有测试目录，不制作一套庞大的形式报告。

```text
python scripts/cardkit.py validate "作品/01_世界书_导入.json"
python scripts/audit_worldbook.py "作品/01_世界书_导入.json" --cases "作品/测试/世界书场景.json" --out "作品/测试/世界书审计.json"
```

`--out`目标存在默认报错，更新自己生成的检查记录可加`--overwrite`。没有场景文件时仍可做静态检查，但状态为`not_run`，不能宣称通过触发测试。

## 场景文件

参考 [cases样例](../assets/worldbook-cases.example.json)，替换教学人物和条目选择器。选择器是准确条目ID或唯一中文entryName；同名条目用ID。空用例、未知选择器、重复case名称、错误角色与类型会报错，防止空跑冒充通过。

- `requiredCoverage`：本轮需要保证能触发的条目。完整新书列出核心人物、出场入口和关键详档/事件；小修只列相关条目。不能删掉未命中项来伪造通过。
- `cases[].messages`：按真实时间顺序的user/assistant消息数组。扫描深度在本地按消息条数近似计算，不是完整对话轮数。
- `mustHit`：本例应加载的条目；`mustNotHit`：本例不该加载的条目；`onlyHit`：可选，严格限制只允许哪些条目，空数组表示应该零命中。
- `maxCharacters`：可选，本例允许的命中正文原始字符量，空白也计入。先看设计所需信息和实际测量再设预算，不复制样例数字成所有卡的标准。不是token数，不含主提示词/聊天历史/状态记忆。

普通字段默认字面匹配。复杂正则、概率、全词、次关键词等未模拟能力保留`unsupported`，影响本地结论时标为`inconclusive`并返回非零退出码；即使预计相关条目命中也不能当全部通过。平台裁剪、递归与优先级并未模拟。脚本也不能判断一条内容是否真正含有人物动机或内容里的状态前提是否成立。

## 应覆盖的自然场景

| 类别 | 例子 | 检查目的 |
|---|---|---|
| 名称与别名 | 我想找林师傅 | 能加载核心，别名不撞别的人 |
| 无姓名进入 | 去旧邮局对街的书店看看 | 命中入口，入口正文足够引出预设NPC |
| 专题查询 | 问林知夏的旧事 | 加载正确详档，不加载其他人的全部过往 |
| 反例 | 我想聊自己的过去 / 今天公司挺忙 | 不因宽泛主题词误载别人的档案 |
| 指代续接 | assistant刚介绍林知夏，user说继续 | 最近窗口保留该人物，不能只有精确查询才认识她 |
| 场景退出 | 离开书店后若干条消息，再去别处 | 窗口之外的旧人物/事件退出，防止长期堆积 |
| 歧义/同名 | 店里说“修书师”时有几个人 | 唯一名定位；职业通用词只引入该处合理人物 |
| 条件事件 | 已经完成旧信查询，又回店 | 触发与事件发生分离，重入是否重复播开场另做内容审查 |

广义词偶尔有合理用途，如单人物小卡的“她”；警告只是候选风险，结合实际用例决定，不能机械全部删除。读不到前文的孤立“继续”与有上下文的“继续”要分开测试。

## 报告怎样用

脚本统计条目/正文总量、常驻候选量、命中字符量、未被正例确认的条目；筛选相同/高度近似正文、共享关键词与宽泛词、无关全局扫描、待补充占位语。近似匹配基于字符片段，只作审阅提示，不给文学质量评分，也不据此删除资料。原始内容不会复制进报告。

案例`passed`只说明列出的预期与本地支持的匹配规则一致。返回码：0=结构和已执行案例无失败/未知，1=错误或明确失败，2=存在未模拟能力。静态warnings需人工解释或修复；无用例即便返回0也只代表静态检查运行成功。

最后在检查记录中简短填写**条目名/发现的问题/已修正事实或保留理由/验证范围**：
1. 主要人物逐一确认年龄、年表、经历如何影响现在；配角按用户要求覆盖。
2. 抽取身份、亲属、地位、称谓、资源归属的交叉引用，确认不会互相打架。
3. 无姓名出场路径不仅要命中，入口内容还应有身份、动作和可回应事项；脚本不能替你确认这一点。
4. 关系、性格反差与分支有原因；不是所有人物复制同一种身世、口吻、亲近路线。
5. 代表场景命中量超预算先查重复/宽泛触发/扫描范围，再调整结构；不先删必要的人物细节。

已有素材不需要为了运行此脚本重建ID或抹掉平台扩展字段。未真实导入/试玩就明确“本地检查完成，线上待验证”。工具报错或缺环境时保留检查计划与未执行状态，不编造成功结果。
