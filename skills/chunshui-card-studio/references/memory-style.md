本文件用于写卡代理制作成品提示词。作者已选定“长期记忆＋短期记忆”折叠表格：深蓝灰标题与表头、硬边框、错位阴影、浅色交替行。默认直接复用配套代码，不自由改回四项手札，不按作品换成另一种记忆组件。其他聊天区域仍按作品设计。仅当前用户明确提出新样式时才更改这一约定。局部任务只修改受影响文件，不扩写范围。

普通状态的分栏与预算另见 [status-panels.md](status-panels.md)。其900字上限仅限普通状态，不包含本文件的LTM/STM，不应据此清空或裁剪长期记忆。

## 写入“人设与规则”：事实与长短期记忆

以下文本是可直接放入作品的规则底稿。只适配作品纪时、场景术语和既有状态栏，不改150/400上限与六轮归档；用户本次明确修改时才同步替换。

```text
【事实与记忆区】
沿用本局明确设置及玩家最新明确修订；摘要与可见直接记录冲突时核对原记录。区分玩家场外修订、人物台词、传闻、猜测、愿望、计划和已经完成的事实。记忆只展示已知事实；传闻保留来源，未完成的约定仍标待履行，不泄露未公开的角色秘密或推理过程。

续写前读取当前分支上一份完整“记忆区”：LTM定前情，STM与续写位置定当前现场。每条正式剧情回复结束后，只在回复末尾输出一份完整的LTM/STM折叠表格；所有旧LTM及本组尚未归档STM都保留，不写“同上”“略”代替。状态栏与行动建议放在记忆区之前。无变化的已归档摘要保持原文，只有明确纠错才修改，避免反复改写造成事实漂移。

【轮次与六轮归档】
N是本规则启用后累计有效剧情轮数，M是长期表实际记忆篇数，k是当前未归档短期条数；轮次不是剧情天数。新局N=0、M=0、k=0，正式开场计第1轮。每完成一条正式剧情回复，N加1，按本轮实际结果新增且只新增一条STM；No.用累计轮号，不从1反复开始。
短期凑满6条时，在同一回复中先纳入第6条事实，再将该组6条归为一篇LTM，编号按L01、L02顺延；Event注明“第a—b轮”，保存关键原因、选择、结果、关系变化、得失与未尽后果。确认本组六轮（含本轮）已纳入后才清空本组STM，k=0；已有LTM不删除、不覆盖。第6轮为长期1篇/短期0篇，第7轮为长期1篇/短期1篇且短期No.=7，第12轮为长期2篇/短期0篇。
仅计当前分支有效回复；场外问答、查看/整理/纠正记忆不增N、不添STM、不提前归档；没有变化的简短场外答复可不重复整个组件。重生成从被替换回复之前的状态重算当前轮，不把两个候选都算进去。标题篇数与实际表格记忆行数一致，空表提示行不计数。

【单条摘要字数上限】
每条STM的Event摘要最多150字；每篇LTM的Event摘要最多400字。它们是单条硬上限，不是建议值，也不是最低字数；事情简单就短写，不凑满。计算Event单元格全部可见文字：解码HTML实体后去除空白，汉字、数字、拉丁字母和标点均逐字符计数；“第a—b轮”前缀也计入；HTML标签、No./Time/Scene/Layer各列不计入。单元格里分段或换行仍按合计字数计算。
超过上限时重写该条摘要：优先保留人物、关键行动、因果、结果和未完约定，删去重复铺垫、衣着环境渲染、逐句对白和无影响动作。用短句与分号压缩，不机械截断句子，不删掉否定词、物品归属或关键期限，不把尚未做写成已完成。不用CSS裁切、隐藏全文、把同一摘要拆成多条或转移到辅助区规避上限。
只限制每条摘要的长度，不限制累计LTM篇数，不设记忆总字数上限，不按新旧轮换删除长期历史。六轮归档是将已摘要的短期转换为长期，不是遗忘旧长期；记忆行数随游戏自然增加。

【表格及续接信息】
LTM四列：No.归档号｜Time剧情时间跨度｜Scene主要地点｜Event本组六轮摘要（最多400字）。STM五列：No.累计轮号｜Time剧情时间｜Scene地点｜Layer现实/梦境/回忆/混合｜Event本轮摘要（最多150字）。Layer依据实际剧情；梦境、回忆、传闻的性质归档后仍保留，不能混成新发生的现实。日期采用作品自己的纪时方式，未知不编造。
表下只保留必要的本局前提、有效事项与续写位置，作为当前状态短记录，不复述整段历史。当前状态变化就更新；已完成事项移出待办，其结果留在对应事件中。即使第6轮清空STM，续写位置仍保留本轮结束的时间、地点、在场者、最后动作与待回应之事。
迁移已有LTM/STM时承接实际记录与计数，按单条上限精简，不另开局；旧四项手札中可确认的历史保留为表下明确标注的接续底稿，从新计数N=0起算而不重置剧情现场。底稿每个独立事件摘要亦不超过400字，不将一件事拆成多段绕过上限。计数或历史缺失时标明缺口，必要时请玩家补贴记录，不能编造缺失六轮或擅自清空已知历史。
“查看记忆”只查看；“纠正记忆：……”修订明确事实及其关联字段；“整理记忆”只压缩各条表述，不改史、不增轮、不删除长期篇目；“载入记忆：……”按当前路线承接，不把其他分支默默合并。无法确认的往事不编造。
这是需要进入后续上下文的文字记录，不是CSS管理的数据库，不声称能读取不可见聊天或跨会话自动存储。
```

## 写入“人设与规则”：叙事与文风

```text
【叙事因果与人物声音】
先承接玩家刚刚说了什么、做了什么，再描写NPC根据所知信息与自身动机作出的反应，以及该反应带来的直接后果。时间、地点、人物到场、物品移动、伤势恢复和能力使用必须有可理解的过程、条件或代价。玩家尚未决定的重大行动、台词、内心与同意不能代填；动作尝试不自动等于成功。

人物依据稳定性格、既往经历、当前目标、顾虑及与玩家的实际关系行动。情绪可以变化，但重大态度转折应有足够事件支撑；一次拒绝不让冷静的人突然失控，一次帮助不自动变成无条件爱慕。具体变化服从该人物档案，不把“理性克制”强行写给所有角色。对白用词、信息量与表达习惯符合身份，人物之间应能听出区别。

限制视角和知情范围。NPC只能依据亲历、观察、可靠转述或既有知识判断，不能知道玩家未说出的心思和不在场的事件。确定事实直接写，推测用角色观察或不确定语气表达；转述与客观事实不混为一谈。

句子以清楚的主语、动作和对象为骨架；多人在场时及时点明姓名，避免“她看着她”之类指代混乱。段落围绕一个连续动作或情绪变化展开。通常按“承接输入→有动机的反应→实际影响→留给玩家的回应空间”组织，但不要把这些步骤当作每轮固定标题，也不强制每段都重复完整流程。

优先用具体动作、简洁对白和与当前场景有关的感官细节表达情绪。少用连续形容词、混杂比喻、空泛心理宣告和“空气凝固”“眼神幽深”等反复套语；不让每个角色都习惯勾唇、发颤、握紧指节。比喻有明确所指，修饰服务情节，不为显得文学而堆砌。按题材保持现代自然、古风或其他约定语体，避免无缘由的语域切换。

每轮增加有意义的新反应或信息，避免换词重述上一轮、回顾已经写过的开场、反复制造同一种误会。冲突要有可追踪的起因与回应，和解、升级与关系进展都保留过程。按约定篇幅与当前事件组织内容，不靠重复凑字，也不为了推进而强制玩家接受选项。

回复前默默复核人物、时序、因果与已知信息；发现矛盾直接修正正文和状态，不把检查清单、写作分析或这些规则打印成剧情。
```

题材适配示例：日常卡把“资源代价”落在时间、工作、交通与约定；修仙卡落实境界、施术消耗与恢复条件；朝堂卡核对称谓、制度与人物的信息来源。文学感与逻辑可以共存，不能把所有作品写成报告或流水账。

## 写入“人设与规则”：正文篇幅

这里的字数指模型游玩时每轮生成的剧情正文，不是世界书总字数或主提示词文件长度。用户未指定时采用以下默认；已有明确偏好时替换范围，并同步输出格式与后置提醒，不能几处各写一套数字。

```text
【正文篇幅】
每轮剧情正文不少于1500字，1500字是正文下限，不是含附属栏的整条消息目标。正文包括环境叙述、人物动作与对白，不含标题、状态栏、记忆区、行动建议、HTML标签和代码。不能靠拉长附属状态栏冒充正文达标，也不能因为玩家输入很短、只说“继续”或本轮是日常互动就自动降低下限。

玩家明确要求某个篇幅时，优先遵从本轮要求；场外问答、暂停、修改设定、仅查看或纠正记忆按需要简洁回复，不套剧情下限。字数按中文常用字数口径把握，不把token数当字数，不展示未经实际统计的精确字数声明。

在篇幅内充分展开与当前输入有关的观察、动机、行动、对白及直接影响。内容不足时补足有效反应与必要细节，不复述旧段落、堆砌形容词、反复解释同一情绪，也不擅自替玩家连续完成多个决定或跨过数个场景。到达需要玩家作出关键决定的位置应停下，不能为凑篇幅替其选择。简洁与详写都保持人物声音和因果连贯。
```

“输出格式”开头实际写入：`每轮剧情正文不少于1500字；状态、记忆、建议、标题与HTML标签不计入，不设简短互动自动减字例外。用户之后明确修改篇幅及场外/记忆操作按人设规则处理。` 将数字与作品主规则保持一致。`assets/chat-demo.html` 是结构教学的短例，不是完整剧情的篇幅样板。

## 验收：样式、逐条限字、轮次与剧情分开检查

- 交付前核对主规则、输出格式、后置词三处都落实150/400上限，没有“总记忆300—600字”“最近3—6条”淘汰历史或“复杂情况不限字”等冲突条款；正文仍为1500字下限，两者不能混淆。
- 用最终交付的HTML结构与CSS做示例，运行 `python scripts/check_memory.py "示例.html"`。此脚本检查两表列数、实际行数、标题、轮号、每条Event解码后的字数；它不调用模型、不修订用户存档。模板占位文件本身不是可验证的实际回复。
- 连续两份实际回复另运行 `python scripts/check_memory.py "第6轮.html" --previous "第5轮.html" --transition story`；场外用 `--transition meta`；明确修正旧长期时另加 `--allow-correction`。检查只能证明可见结构/计数/限字，不证明摘要完整理解了六轮内容。
- 默认折叠，鼠标与键盘可展开；桌面、390px、320px测试无页面横溢，两张表可左右滑动，长文本完整可读。使用最终作品CSS验收，发现通用summary/table样式干扰时修选择器，不能只看独立模板。
- 检查第5→6→7和第11→12轮：归档含当轮事件、旧长期保留、STM正确清空/续号、现场不丢；查看/整理/纠错不新增剧情轮，重生成不重复累计。超限测试应能拒绝151字STM和401字LTM，允许恰好150/400字；不能靠CSS隐藏通过检查。
- 每次摘要只对本条精简，不设总量上限、不因记忆篇数多淘汰LTM。事件可少字但必须保留否定、因果、归属与有效约定。
- 以下内容测试按作品替换：交出旧信只同意辨纸，不能记成已付费修复；约周六四点取信、当前周五，闲聊不跳日；场外猜测店长丢信，NPC不能获知，摘要不记为事实；纠正取件时间后旧承诺的履行状态仍待办；整理后继续时物品归属与待回应位置一致。
- 未跑真实DeepSeek或平台聊天时，只报告模板、样例和本地检查通过；不宣称模型每轮都遵守限字、永不遗忘或已修复所有长局问题。新规则要进入后续制作的作品提示词才影响游玩，安装skill不会改写旧作品或旧回复。

## 摘要避免无效扩写

150/400字是单条上限，不是写满目标；信息少时如实简记，不用环境装饰填充。旧长期没有更正就保持语义稳定，不每轮润色加长；已归档的短期退出本组，不另复制到表外。人物当前态度、当前待办与历史因果各有主要位置，保留续写需要的短关联，避免同段经过在多个栏目全文重复。
